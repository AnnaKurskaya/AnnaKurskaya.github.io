# Сайт-портфолио Anna Kurskaya

## Что мы строим

Это личная **SPA-библиотека проектов**. Сейчас сайт представляет собой атмосферный первый экран-каталог: имя владельца по центру, 3D-карусель и подробное описание проекта 1 ниже.

Текущий первый экран:

- боковая панель убрана;
- используется тёмная розово-винная тема;
- стеклянные карточки расположены в 3D-карусели;
- стрелки, точки прогресса, клики по карточкам и клавиши ←/→ меняют активный проект;
- карусель перелистывается вручную стрелками, точками, кликом по карточке или клавишами ←/→;
- фон оживлён частицами и связанными геометрическими линиями через `@tsparticles/react`;
- в каталоге пока три карточки `проект`; первая ведёт к описанию учебной экспертной системы для Homescapes;
- ниже карусели находится glass-раздел проекта 1: архитектурная схема, рабочая и экспертная базы данных, модель параметров, формула ранжирования, 20 стратегий и план реализации.

Визуальное направление — ночной винно-розовый интерфейс: глубокий plum-фон, мягкие розовые свечения, frosted glass, тонкие границы и крупная типографика. Новый концепт сохранён как `design-concept-v2.png`.

## Как будет расширяться каталог

Карусель не зашита в разметку проекта. Проекты описываются данными, поэтому со временем можно добавить:

- реальные названия и описания;
- превью или изображения проектов;
- отдельный маршрут `/#/project/:slug`;
- открытие репозитория и live demo;
- фильтрацию или второй режим отображения каталога.

На следующем этапе список проектов можно вынести в JSON/Markdown или получать из GitHub API. Для GitHub Pages лучше начать со статических данных в репозитории: сайт останется быстрым и будет работать без сервера. Полное описание задания проекта 1 сохранено в `.docs/PRODUCT_PASSPORT.md`.

## Что доступно на GitHub Pages

GitHub Pages — это статический хостинг. Он умеет отдавать собранные HTML, CSS, JavaScript, изображения и файлы Markdown, но не запускает серверный Node.js-код и не хранит секреты.

Для этого проекта подходит схема:

1. React + Vite собирает исходники в папку `dist`.
2. GitHub Actions запускает сборку после push в `main`.
3. Готовая папка `dist` публикуется через Pages Deploy Action.
4. Пользователь получает адрес вида `https://<логин>.github.io/<репозиторий>/`.

В репозитории уже добавлен workflow `.github/workflows/deploy.yml`. В настройках репозитория нужно один раз выбрать **Settings → Pages → Source: GitHub Actions**.

Важно: GitHub Pages не умеет серверный fallback для произвольных URL. `HashRouter` уже подключён как основа будущей маршрутизации, а текущая карусель работает на локальном состоянии. Если позже понадобится чистый URL без `#`, можно перейти на копирование `index.html` в `404.html` во время сборки.

## Можно ли использовать FSD

Да. Для этого сайта FSD (Feature-Sliced Design) подходит хорошо: он отделяет бизнес-сущности, страницы, виджеты и общие компоненты. Сейчас заложен облегчённый каркас:

```text
src/
├─ app/                    # запуск приложения, глобальные стили
├─ pages/home/             # композиция главной страницы
├─ widgets/app-shell/      # оболочка, фон и particle layer
├─ entities/project/       # модель и данные проекта
└─ shared/ui/              # particle background и общие UI-элементы
```

Дальше можно добавить `features/project-filter`, `features/theme-switcher`, `widgets/project-detail` и `entities/article`. Правило простое: страницу собираем из виджетов, виджеты — из фич и сущностей, а общие кнопки, иконки и токены остаются в `shared`.

## Как смотреть текущий результат

```bash
npm install
npm run dev
```

После запуска Vite покажет локальный адрес, обычно `http://localhost:5173`. Для проверки production-сборки:

```bash
npm run build
npm run preview
```

Команды одинаковы для Windows, macOS и Linux. Node.js 22 LTS или новее будет достаточно.
